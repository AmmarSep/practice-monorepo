# 14-day interview practice plan

Use [the Java topic index](../interview/java/README.md) to locate each exercise.
Aim for 60–90 minutes daily: 10 minutes review, 35 minutes solving without the
answer, 20 minutes edge cases and explanation, then 10 minutes recording mistakes.

| Day | Focus | Deliverable | Done |
| --- | --- | --- | --- |
| 1 | Strings: reverse, word count, duplicate characters | Explain character vs word processing; check blank input | [ ] |
| 2 | Arrays: maximum, second distinct maximum, sum | Handle negative values and repeated maxima | [ ] |
| 3 | Frequency maps and unique values | Explain why insertion order matters | [ ] |
| 4 | Searching, sorting, array APIs | Explain the sorted-input requirement for binary search | [ ] |
| 5 | Numbers: prime, factorial, Fibonacci, palindrome | Cover 0/1, invalid input, and overflow | [ ] |
| 6 | Streams: filter, map, collect, grouping | Rewrite two stream solutions using loops | [ ] |
| 7 | Timed review | Solve three earlier questions in 45 minutes | [ ] |
| 8 | OOP: encapsulation, inheritance, polymorphism | Explain each with one concrete example | [ ] |
| 9 | Interfaces, abstraction, lambdas | Explain abstract class vs interface and functional interfaces | [ ] |
| 10 | Collections and object sorting | Explain equality, hashing, Comparable vs Comparator | [ ] |
| 11 | JVM memory, strings, exceptions | Explain stack vs heap and checked vs unchecked exceptions | [ ] |
| 12 | Threading and backend review | Explain synchronization, executors, HTTP, and JDBC resource handling | [ ] |
| 13 | Mock interview | Two coding questions and 20 minutes of Java discussion | [ ] |
| 14 | Weak areas and final revision | Re-solve mistakes without looking at previous code | [ ] |

For days 10–12, consult the `Fresher`, `FrequentInterviewQuestions`, and
`Intermediate` reference links in the topic index. Those older snippets are not
all standalone, dependency-free applications.

## Coverage gaps to practise separately

The existing repository is strongest in Java basics, streams, and small array/string
questions. It is not a complete interview syllabus. Depending on your target role,
add dedicated practice for two pointers/sliding windows, linked lists, stacks/queues,
trees, graphs, recursion/backtracking, dynamic programming, SQL, and system design.
Add one well-named exercise per problem instead of another `Again` or `Practice1` copy.
